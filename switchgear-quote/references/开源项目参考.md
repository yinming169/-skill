## 二、逐个研判

### 1. `lchangg/CAD-BOM-Automation-System` —— 结构值得学，算法不值得学

**读了**：`work/classify_device_candidates.py`（5869 字符）、`examples/sample_bom.json`、`docs/architecture.md`、`docs/development-history.md`

#### 精华：可追溯性的数据结构

它的每条 BOM 记录长这样：

```json
{
  "category": "断路器",
  "specification": "3P 200A",
  "quantity": 1,
  "source": {
    "original_text": ["3P 200A"],
    "coordinates": [{"layout": "Model", "x": 120.5, "y": 80.25}],
    "recognition_rule": "pole + current pattern"
  }
}
```

三个值得注意的细节：

- `original_text` 是**数组**——一行里多个文字可归并到同一物料
- `coordinates` 带 `layout` 名（Model / Paper 空间）——DXF 两种坐标空间不混
- `recognition_rule` 记录**哪条规则命中**，而不是一个模糊的置信度

我们的 `evidence` 现在是 `"图块 DYDQ0201@高低压系统"` 这种字符串，**无法定位回图纸**。这是真差距。

#### 糟粕：识别规则比我们弱一个量级

```python
RATING_RE = r'\b[1-4]\s*P\s*(?:[A-Z])?\s*\d+(?:\.\d+)?\s*A\b'   # 只认 "3P 200A"
SPD_RE    = r'\b\d+(?:\.\d+)?\s*KA\s*SPD\b'                      # 只认 "20KA SPD"
CABLE_RE  = r'(?:mm2|mm²|×|\*)'                                   # 太宽，× 会误判
BREAKER_MODEL_RE = r'\b(?:DZ\d+|C(?:6[03]|32|65|60)\w*|CM\d+\w*|...)\b'
```

- **不区分微断/塑壳/框架**，全归"断路器"
- 数量靠 `*N` 后缀猜
- 没有型号规范化、没有分断能力、没有柜型识别、没有铜排/柜体推算
- 只做到"单柜验证"规模，没有量产验证

**结论**：抄 `source` 结构，别抄正则。我们的 `PATTERNS`（15 类、上百系列）+ 通用代号规范化 + 分断能力 + 柜型识别，已经领先它一个身位。

#### 它的多租户架构（organization / master-data / quotation / supplier-import）

这是 Web SaaS 的产物（多企业隔离、服务端鉴权、报价快照 PDF）。**我们是单机报价工具，用不上**。

唯一可借的一点：**公共参考价 vs 企业实际价** 分开。我们可以把价格库拆成「参考价（网上公开）」和「成交价（自己历史）」，匹配时优先成交价。

### 2. `jhonat23/IEC-60895-busbar-shortcircuit-calculation` —— 唯一"我们完全空白"的硬技术

**为什么重要**：我们选铜排只看**载流量**，没校核**短路时的电动力**。这是安全隐患——铜排选小了，短路时会被电动力打弯、打飞。

**它的内容**（IEC 60865）：矩形铜排三相等距布置，短路电流产生的电动力

```
F = 2 × (I_k'' )² × l / a × 10⁻⁷   (N)     两平行导体间电动力
σ = F × l / (8 × W)                  (N/mm²)  母线弯曲应力
W = b × h² / 6                       (mm³)    矩形截面抗弯模数
```

判据：`σ ≤ σ_allow`（铜排许用应力，硬铜约 140 N/mm²）

**落地设计**（不改变表格）：
- 新增 `scripts/check_busbar.py`，输入短路电流（从框架断路器 Icu 或图纸标注取）、铜排规格、跨距、相间距
- 输出：`σ` 与许用值对比、是否通过
- **结果只进"复核提示"或单独一份校核报告，不进报价表**

### 3. `rwl/iec60909` / `Sparlectra.jl` —— 只抄公式，不抄实现

- `rwl/iec60909`（Rust）：三相短路电流计算，代码短好读，公式可直接照搬
- `Sparlectra.jl`（Julia）：IEC 60909 + 潮流 + N-1，实现完整但生态不兼容

**我们的用法**：短路电流 `I_k''` 是母排校核的输入。可以从框架断路器 `Icu` 反推，或按变压器容量 + 阻抗电压估算：

```
I_k'' = S_n / (√3 × U_n × u_k)     （变压器出口三相短路）
```

不需要完整潮流计算——报价阶段用不到。

---

### 4. `Pdhruv15/LV-Design-Suit` —— 只抄一句话

功能很全（单线图、负荷表、选型、压降、短路、接地、保护配合、变压器/发电机、功率因数校正），但 Electron/TS 技术栈，代码抄不了。

**唯一值得抄的是态度**，README 原话：

> "计算只是一次设计校核，不能替代工程师的正式计算"

我们的铜排用量、柜体部件全是**推算值**，报价单上必须明确标注"需复核"，不能让人当成正式计算书。这一点我们现在做得还不够硬——只在"复核提示"页写了一句，应该在**汇总页**也标注。

### 5. `jihys/electrical-sld-bom-extraction` —— 抄思路，不抄技术

- Agentic 流水线 + Azure OpenAI + Document Intelligence：**我们离线，用不了**
- 真正有价值的是它的 **Streamlit 分步确认**：选页 → 图形检测 → 盘区与间隔

**我们的简化版**：出正式报价单前，先出一份 **`核对表.xlsx`**（含柜号、原始文字、坐标、命中规则、置信度），人工确认后再出正式表。不需要 UI，一个 Excel 就够。

### 6. `alliander/switchgear-thermal-model` —— 暂缓

按柜体规格 + 负荷曲线 + 环境温度算柜内温升。有价值，但：
- 需要环境温度、负荷曲线，图纸里没有
- 优先级低于母排电动力校核

**暂不做，记录备查。**

## 四、一句话总结

**这批项目里，只有"可追溯性"和"母排电动力校核"是真金；其余要么我们更强，要么根本不是同一个场景。**

识别算法我们领先，不要被"同路线"三个字带偏去重写；缺的是**可追溯**（工程可复核）和**短路校核**（安全底线）。
